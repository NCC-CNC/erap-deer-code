Changelog

v0.2 release - 2026-11-20

Structural code changes

  • Rebuilt from 19 loosely-coupled scripts with hardcoded absolute paths into a toml-config-driven pipeline: setup.toml for all paths, numbered step scripts (01_setup.R .. 09_gather_and_write.R) + fct_ helpers, one entry point (__pipeline__.R), matching the conservation-profiles pattern.
  • Pipeline now runs over two landscape sets – ecoregions and Priority Landscapes – via two setup.toml files (setup_ecoregions.toml / setup_priority_landscapes.toml), producing two outputs with an identical schema. Code uses generic “landscape” terminology throughout, not “ecoregion”/“boundary”.
  • New landscape_id column is the universal per-run join key across every step’s checkpoint CSV, replacing ECOREGION_ID as the internal join key.
  • Reused already-verified functions from conservation-profiles instead of re-writing them: fct_read_feature.R, fct_read_raster.R (copied verbatim); build_species_stack() (copied verbatim), load_species_meta()/summarise_species_tab() (adapted – see “Output table & calculation changes” below). fct_intersect_vector_value.py’s intersect_vector_value() was rewritten as a bulk-pass function (intersect_vector_values(), one dissolve-by- landscape_id pass instead of one call per landscape), plus a new intersect_vector_geoms() for callers that need the clipped geometry itself (not just a summed area) to then extract a raster against it. A parallel bulk raster helper, intersect_raster_values() (R/fct_intersect_raster_value.R), does the same for rasters – one exact_extract() call across every landscape at once. Porting these back into conservation-profiles is tracked in CONSERVATION_PROFILES_CHANGES.md.
  • Species raster prep (5a) referenced only via setup.toml as a pre-generated input, same as before. The prioritizr optimization chain is kept in-repo under data_prep/8 prioritizr/, its outputs feeding ERAPs_v2 for setup.toml to reference, same pattern as every other data_prep/ script.
  • New data_prep/ folder for one-time GIS prep scripts that run before the pipeline, building reference layers the pipeline itself just reads: ecoregions (CTEF v2.2), Priority Landscapes x ecoregions overlap attribution, CPCAD+NCC 2025 (unclipped and terrestrial-clipped), species tif extraction + metadata filtering + protected-area recalculation, the WTW erase, habitat source gathering, and Indigenous Territories x ecoregions/Priority Landscapes intersection. Their generated GIS outputs all live outside the repo (C:/Users/marc.edwards/Documents/PROJECTS/ERAPs_v2), not inside this repo’s own data_prep/ folder.
  • Every numbered step reads its own setup.toml inputs + the step-02 landscape table, writes one checkpoint CSV to processing_dir, and can be re-run independently (by sourcing just that step) if a later step fails.
  • Deferred/dropped from this pass: 5b/5d species QA checks (deferred, not ported); 8_clip_data_for_pdf_maps.py (out of scope); fct_calculate_targets.R/fct_init_metadata.R/fct_sci_to_common.R (not ported into the new pipeline – fct_calculate_targets.R is still used directly by data_prep scripts, the other two are unused anywhere in the repo).
  • 6_action_recommendations.R ported as R/08_actions.R, generic over landscape_id (both landscape sets) instead of one hardcoded, ecozone-filtered ecoregion shapefile looped one row at a time. Two new checkpoint CSVs per run (actions_table.csv long, actions_summary.csv wide), same shape as the legacy script’s two outputs. actions_summary.csv (wide, one row per landscape) is joined into 09_gather_and_write.R’s table, matching the legacy 7_gather_tables.R’s own join of action_recommendations_wide.csv; actions_table.csv (long, one row per landscape per triggered action) is not, for the same one-row-per-landscape reason species isn’t. Three triggers had to be reconstructed rather than reused verbatim, since their legacy inputs no longer exist:
    • ABC2/ABC3 originally counted SAR and Critical Habitat species together; CH is no longer tracked anywhere in this pipeline’s species data (only the SAR (NCC AOH) theme survived the Theme rename), so these two count SAR alone now.
    • REST2’s old input (% of unprotected land that’s modified) was retired by #29; recomputed explicitly from modified_km2/protected_modified_km2/landscape_km2/protected_km2 to keep its own definition and 30% threshold unchanged, rather than substituting one of #29’s new full-landscape percentages (different denominator).
    • STEW1/PARTNER1 need NCC’s fee-simple(+CA) properties as their own layer – data_prep/"3 prep_cpcad_ncc_2025.py" now persists ncc_fs_ca_2025_dslv (fee simple + conservation agreement) and ncc_fs_2025_dslv (fee simple only) instead of dissolving them away into the merged CPCAD+NCC layer (setup.toml’s new ncc_fs_ca_path/ ncc_fs_path).
    • ABC1, ABC4, ABC5 ported onto existing columns (protected_pcnt, wtw_percent, wtw_area_km2) unchanged – wtw_percent’s own definition already changed under #18 before this port, so ABC4/ ABC5’s 20%/10,000km² thresholds now fire against the erased-protected WTW layer, not the legacy un-erased one (confirmed expected via the v1 comparison below, not a bug).
    • REST1‘s legacy input (a combined protected + unprotected-intact coverage estimate, not a plain column) doesn’t exist anywhere in this pipeline’s tables – an earlier pass wired it to protected_intact_pcnt directly, which is a different quantity under #29 (the protected/intact overlap, not the combined estimate) and fired almost everywhere it shouldn’t have. Fixed: REST1/REST2 both recompute the legacy formulas explicitly from intact_km2/modified_km2/ protected_intact_km2/protected_modified_km2/landscape_km2/ protected_km2, including the legacy script’s own denominator restriction (the pressure-raster-classified subset of unprotected land, not the full unprotected land area) – keeping both triggers’ definitions and 30% thresholds unchanged from the legacy script.
    • Validated the full action-recommendations port against the final v1 output (action_recommendations_wide.csv, not the earlier, stale archived ERAP_attributes.csv snapshot, which predates it by 10 days): ABC1, STEW1, REST1, REST2, PARTNER1, and Restoration_count match exactly (0/149 ecoregions mismatched); ABC2/ABC3/ABC4/ ABC5/ABC_count mismatch only where already expected from the SAR-only and #18 WTW-redefinition changes above.
    • New reference table tables/ERAP Action recommendation reference.xlsx (action ID -> CMP 2.0 action, description, indicator, trigger condition), checked into this repo (setup.toml’s new [actions].actions_reference_path) rather than left in the old erap_code repo it used to live in.

Output table & calculation changes

  • wtw_percent redefined as % of the whole landscape (wtw_area_km2 / landscape_km2 * 100), not % of the unprotected remainder – and wtw_area_km2 itself now comes from intersecting wtw_erased_protected (WTW solution, CPCAD+NCC erased – erap-deer-code#18) against each landscape, replacing raster zonal stats against the un-erased solution. No includes_km2 column – retracted once #18 removed the need for it.
  • erap-deer-code#29: unprotected_intact_pcnt/unprotected_modified_pcnt (computed against the unprotected remainder only) are replaced with four full-landscape figures – intact_pcnt, modified_pcnt, protected_intact_pcnt, protected_modified_pcnt – all four sharing one denominator, intact_km2 + modified_km2 (not landscape_km2, since the pressure raster pair won’t always fully cover the landscape polygon exactly – this denominator choice guarantees the two top-level percentages sum to 100 regardless). New raw-area columns intact_km2, modified_km2, protected_intact_km2, protected_modified_km2 also land in the output table.
  • Collapsed the ecoregion vs. ecoregion_inland duplication to a single reference landscape polygon per loop (the land-clipped one, not the full extent) – dropped the full-extent-only columns: ecoregion_km2, protected_km2 (full), protected_pcnt (full), wtw_area_km2 (full), wtw_percent (full).
  • Column renames from the single-polygon collapse + generic landscape terminology: ecoregion_inland_km2 -> landscape_km2; protected_inland_km2/_pcnt -> protected_km2/_pcnt; wtw_area_inland_km2 -> wtw_area_km2; wtw_inland_percent -> wtw_percent; pcnt_ecoregion_forest/grassland/wetland/lakes_cover -> pcnt_landscape_..._cover.
  • Habitat type renamed: shoreline -> coastline (habitat_shoreline -> habitat_coastline, shoreline_km -> coastline_km, etc.) – the underlying dataset changed from shoreline_merge to CanCoast, so the name changed to match.
  • Forest/grassland/wetland habitat sums now intersect the same land-clipped (terrestrial) landscape polygon lakes/rivers already used (previously intersected the full extent) – expect small differences right at coastlines vs. the historical values.
  • Coastline is the one habitat type that does NOT use the terrestrial landscape polygon: every landscape now has a second, marine-buffered polygon (extending into the marine area), and coastline cover (coastline_km) plus coastline’s own protected/WTW overlap (coastline_protected_km/coastline_wtw_km) all intersect against that marine polygon instead – fixing the same undercount issue #24 originally found (clipped terrestrial boundaries lose real coastline length CanCoast would otherwise credit) plus capturing protected/WTW area that extends past the terrestrial land base into the water. Applies to coastline only – no other habitat type, pressure, or landscape-level metric uses the marine polygon.
  • Dropped the second rivers dataset (rivers_1M_*) – only one rivers dataset (matching conservation-profiles’ habitat_rivers) is carried forward.
  • New habitat type: peatlands (vector, habitat_peatlands) – same non-linear cover-type pattern as forest/grassland/wetland/lakes (peatlands_km2/pcnt_landscape_peatlands_cover, its own pcnt_peatlands_protected/pcnt_peatlands_wtw, zeroed out when cover rounds to zero same as the other four). Not in the original erap-deer-code scope – added 2026-10-20.
  • Species: Canada_Protected_km2 (and the Canada_Protection_Gap_km2 it drives) now prefers Protected_Km2_vector/CPCAD-vector-recalculated protected area over the original 1km-grid-based Protected_Km2, per row, where available (data_prep/"7 recalc_species_protected_km2.R") – the grid-based original has a binary-threshold overcount bug – any 1km grid cell with any nonzero protection credits the species its entire area in that cell, no partial weighting – which overcounts protection most for species with small, concentrated ranges.
  • Dropped protection_goal and wtw_eco_pcnt from scope (grep-confirmed neither ever existed in the live code).
  • Action-recommendation columns (ABC1-5, STEW1, REST1-2, PARTNER1, ABC_count, Restoration_count) are in the main attributes table via R/08_actions.R’s actions_summary.csv checkpoint (see “Structural code changes” above), matching the legacy script’s own join.
  • New landscape_id column, always populated in both runs.
  • Ecoregions/ecozones data source switched to the Canadian Terrestrial Ecological Framework (CTEF) v2.2, replacing the old source shapefile – whose French ecoregion names (REGION_NOM) turned out to be corrupted at the raw-byte level and unrecoverable. Along with the switch, the six identity columns are renamed repo-wide: ECOREGION -> ECOREGION_ID, REGION_NAM -> ECOREGION_NAME_EN, REGION_NOM -> ECOREGION_NAME_FR, ECOZONE -> ECOZONE_ID, ZONE_NAME -> ECOZONE_NAME_EN, ZONE_NOM -> ECOZONE_NAME_FR.
  • ECOREGION_ID/ECOREGION_NAME_EN/ECOREGION_NAME_FR/ECOZONE_ID/ ECOZONE_NAME_EN/ECOZONE_NAME_FR: previously would have been NA throughout the Priority Landscapes run; now populated via spatial overlap against the ecoregions layer, /-joined where a landscape spans more than one ecoregion or ecozone. Sliver fragments from boundary misalignment between the two independently-digitized layers are excluded using a validated rule (perim_per_area_km >= 3.0), not a manual area-% guess.
  • Hectares conversion: every *_km2 column becomes *_ha (x 100) in the final assembly step; length columns (rivers_km, coastline_km) stay in km, unconverted.
  • One unified schema now drives two separate output products: ERAP_ecoregions and ERAP_priority_landscapes.
  • Adopted rounding conventions from the data alignment project (erap-deer-code#23): no rounding on intermediate values, final output tables round every value (ha/km/%) to 2 decimal places.
